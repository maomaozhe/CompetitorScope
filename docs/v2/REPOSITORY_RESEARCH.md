# V2 源码研究与跨仓比较产品规格

> 状态：`repo_research_poc` 当前开发主线的产品目标与验收方向；并非全部已实现。更新：2026-09-28。

## 用户要完成的事

用户以自然语言提出源码问题，不需要先查出仓库地址、下载代码或提供 Commit SHA。系统应把“找到正确的代码版本、读懂实现、展示证据”连成一条可审计流程。

典型请求：

1. **跨仓比较**：“分析 OpenClaw 和 Hermes 的 memory 实现差异。”系统分别定位两个项目的代码，围绕存储、检索、注入上下文、生命周期等与问题相关的维度找到实际实现，比较共同点与差异；若某一维度未找到证据，应标为未核实。
2. **单仓链路追踪**：“OpenClaw 的 context 具体怎么实现，链路如何？”系统从可观察入口追到配置、构造、数据流、关键分支与输出，说明调用顺序和边界条件，并把每个关键节点连到源码。

这些名称只是用户问题示例，不预设项目地址、源码结构或实现事实。定位阶段必须先核实身份，不能靠名称猜测代码路径。

## 目标流程

```text
自然语言问题
  -> 识别研究对象、问题类型与可能歧义
  -> 定位候选代码仓库并核实项目身份/来源
  -> 获取源码，固定每个仓库的 Commit SHA 和快照
  -> 围绕问题检索文件、阅读关键实现、追踪调用和数据流
  -> 单仓解释或多仓同维度比较
  -> 验证引用，输出结论、证据、版本与未解决问题
```

仓库发现与下载由受约束的宿主工作流负责；源码研究 Agent 只获得固定版本的只读快照和文件检索工具。临时工作区、运行记录与源码分离。默认不执行被研究仓库的脚本、构建或测试，也不向 Agent 开放宿主 Shell。私有仓库需要用户已有的访问权限；不得因自动定位而扩大外部访问或上传范围。

## 输出与验收

- **来源可确认**：每个研究对象列出项目身份、仓库地址、选定 Commit、获取时间与选择该版本的原因；同名候选或版本歧义需保留。
- **解释可追踪**：回答区分源码直接证明的事实与推断；关键行为给出仓库、Commit、相对路径、行号和逐字片段。引用必须能在固定快照中重放。
- **链路完整度可见**：入口、主要调用、配置/状态变化、关键分支、结果及错误路径按问题相关性覆盖；缺失环节明确写入未解决问题。
- **比较同维度**：多仓任务按同一问题维度并列展示，不把一个仓库中的概念强行映射到另一个；差异结论引用双方证据，缺失证据不等于功能不存在。
- **过程可审计**：保存仓库定位、版本、模型配置、检索调用、错误、耗时、引用检查和最终结果。不能把未经验证的引用作为正式回答展示。

固定仓库版本与固定问题的评测应覆盖：找错仓库、定位不到入口、跨文件调用链断裂、只读工具边界、过时版本、错误行号/原文、比较维度错配、合理弃答及宽问题的耗时和工具预算。业务标准答案需人工核实；“引用存在”本身不证明解释正确。

## 分阶段交付

| 阶段 | 能力 | 当前状态 |
|---|---|---|
| 固定快照问答 | 用户提供本地目录、SHA 与问题；只读检索、回答和引用校验 | `repo_research_poc` 已有独立 CLI/Web 验证 |
| 仓库定位与获取 | 从用户给出的项目名/地址找候选、核实身份、获取并固定版本 | 未实现 |
| 实现链路追踪 | 围绕入口和数据流持续检索，输出有证据的链路与缺口 | POC 可问答，系统化链路覆盖尚未验收 |
| 跨仓比较 | 为多个固定快照建立同维度证据并生成比较结果 | 未实现 |
| 产品化 | 权限、缓存、并发、恢复、评测和与 V2 研究流程/UI 的集成 | 未实现 |

原 V1 竞品分析已封存，保留代码与历史资料供查阅；不再要求它持续作为新功能的 Baseline，也不进行全量架构迁移。后续仓库定位、源码检索、链路追踪和比较集中在 `repo_research_poc` 演进。此前 `src/v2/` 的官方定价方向属于另一条历史方案，见[封存索引](../v1/ARCHIVE.md)。

## RAG 是否需要

**暂不预设向量数据库或长期索引。** 首先以文件路径、符号线索、文本搜索和定向阅读建立基线，测量仓库规模、跨文件召回、回答质量、延迟、成本及隐私边界。只有当固定评测显示这条基线在大型仓库或语义线索稀疏的问题上稳定漏检，且检索增强能带来可重复收益时，再选择具体方案：轻量符号/调用索引、按需摘要、关键词与语义混合检索，或向量 RAG。无论采用哪种检索方式，最终引用仍须回到固定源码快照核验；索引和摘要不能成为事实来源。

是否引入 RAG 的决策记录应包括评测集、失败类别、收益、索引更新与版本一致性、私有源码存储/上传范围和运行成本。现阶段将其列为实验问题，而非产品承诺。
