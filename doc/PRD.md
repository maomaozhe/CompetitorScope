## 待开发

### V2：源码研究与跨仓比较（产品目标）

用户可以直接提出“分析 OpenClaw 和 Hermes 的 memory 实现差异”或“OpenClaw 的 context 具体如何实现，调用链路是什么”。系统需要根据名称定位并核实仓库身份，获取明确 Commit 的源码快照，沿入口、配置、状态、调用和持久化路径阅读实现，再给出可追溯的解释或跨仓比较。用户不必预先准备本地快照或 Commit SHA；仓库同名、版本或访问权限有歧义时应明确列出待确认项。

每条源码结论应关联仓库、Commit、路径、行号及原文；比较需说明两边在同一维度的对应实现、关键差异和未核实部分。仓库代码默认只读，不在研究过程中执行。完整需求、分阶段交付和 RAG 的待定决策见 [源码研究产品规格](../docs/v2/REPOSITORY_RESEARCH.md)。目前 `repo_research_poc` 只验证用户已提供的单仓固定快照问答与引用校验，尚未实现自动定位、拉取或跨仓比较。

以下 P0/P1/P2 清单为既有 V1 Demo 待办；V2 源码研究按上述产品规格独立规划。

### P0（Demo 前必须解决）

- [ ] **流式输出**：每个 Agent 节点运行时实时渲染中间态，Writer 生成报告时渐进式输出，不是黑盒一次性生成
- [ ] **HITL 倒计时修复**：倒计时正常倒数到 0，不反复横跳

### P1（Demo 后）

- [ ] 报告引用质量优化（每个结论有证据，引用准确）

- [ ] 错误处理边界场景（断网、LLM 限流、数据完全抓不到）

### P2（未来）
