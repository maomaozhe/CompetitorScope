# PRD - CompetitorScope 源码研究

> 当前产品主线：`repo_research_poc`。更新：2026-09-28。

## 用户目标

用户可以询问单个项目的实现链路，也可以比较多个项目的同一能力。例如“OpenClaw 的 context 具体怎么实现”或“分析 OpenClaw 和 Hermes 的 memory 实现差异”。系统最终应定位正确仓库、获取并固定源码版本、沿关键调用和数据流阅读实现，然后给出可重放的证据、结论与未解决问题。

## 当前范围

`repo_research_poc` 已提供本地固定快照的单仓问答、Web/CLI、只读检索、引用校验及运行记录。调用者仍需提供快照目录、Commit SHA 和问题；自动定位与拉取、系统化链路追踪、跨仓比较尚未实现。所填 SHA 目前是运行标识，未经过 Git 内容核对。业务标准答案仍待人工核实。

## 后续交付顺序

1. 仓库定位与获取：从项目名称或地址核实仓库身份，取得源码并固定 Commit；在权限或同名歧义时保留待确认项。
2. 实现链路追踪：围绕入口、配置、调用、状态、分支和结果持续检索，展示证据与缺口。
3. 跨仓比较：为多个固定快照建立同维度证据，再生成比较结论。
4. 产品化与评测：覆盖权限、缓存、并发、恢复、成本、质量及私有源码边界。

每个阶段都应保存仓库版本、模型配置、工具调用、错误、耗时和最终结果。引用必须回到固定源码快照核验；“引用存在”不能替代对解释正确性的人工或业务评测。RAG 是否引入尚未决定，依据固定评测中的漏检和收益再选择检索方案。

详细验收口径见[源码研究产品规格](../docs/v2/REPOSITORY_RESEARCH.md)。
